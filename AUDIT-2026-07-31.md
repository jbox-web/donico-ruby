# Donico 1.14.0 — Audit de code

Périmètre : dépôt complet (source de la gem, templates GitLab CI, harnais bash, CI, specs, doc) · Couverture : **66/66 fichiers suivis lus** (44 production + 22 tests/fixtures, 0 fichier généré ou vendorisé).

Ce dépôt porte déjà un `TODO.md` daté de la version 1.14.0 issu d'un audit précédent. Le présent rapport **re-vérifie empiriquement** ses conclusions et se concentre sur ce qu'il n'avait pas couvert. Les findings déjà présents dans `TODO.md` sont marqués `[déjà dans TODO.md]` pour ne pas gonfler artificiellement le compte.

## Sémantiques vérifiées cette session (sondes, pas mémoire)

- `"\1_\2"` en guillemets doubles n'est **pas** une backreference : `underscore("MyApp")` → `"m_pp"` (octets de contrôle 0x01/0x02).
- `YAML.safe_load("version: 3.10")` → `Float 3.1`, `.to_s` → `"3.1"` (perte silencieuse du `0`).
- `["BAR_VERSION=Zm9vCg=="].map(&:downcase)` → `["bar_version=zm9vcg=="]` (base64 cassé).
- `run_cmd` en chemin `rescue` retourne `false` (scalaire) : `result, log = false` → `log = nil` → `[nil].reject(&:empty?)` lève `NoMethodError: undefined method 'empty?' for nil`.
- `Kernel.exec` remplace le process : un hook `after` déclaré autour d'une tâche exec-based **ne s'exécute jamais** (sonde Rake : `"AFTER-HOOK ran"` jamais imprimé, exit 0).
- `{name: "per-matrix"}.merge({name: "top-level"})` → `"top-level"` (l'argument de `merge` gagne).
- `format('100%-x', {})` → `TypeError: can't convert Hash into Integer`.
- `YAML.safe_load` sans options : ancres YAML → `Psych::AliasesNotEnabled`, date non quotée → `Psych::DisallowedClass`, fichier vide → `nil`.
- bash `[ ! -z "${cid+x}" ]` avec `cid=""` → **vrai** (le test est vacué) → `docker kill ''`.
- bash `echo "K=Zm9vCg==" | cut -d '=' -f 2` → `Zm9vCg` (padding perdu) ; `${val#*=}` → `Zm9vCg==`.
- bash `trap f INT ERR EXIT` + `set -e` : `f` est appelée **deux fois** (ERR puis EXIT).
- bash `set -u` + trap référençant une variable assignée plus loin : le trap lève `variable sans liaison` et **masque l'erreur d'origine**.
- `curl --upload-file` **sans** `--fail` sur une réponse HTTP 403 → **exit 0** ; avec `--fail` → exit 22 (serveur local éphémère, supprimé).
- État courant : `mise test` → 64 exemples, 0 échec, couverture lignes **83.52 % (370/443)**. `mise lint-project` → 30 fichiers, 0 offense.
- `bundler ~> 4.0` est satisfaisable (bundler 4.0.17 installé) — hypothèse de contrainte impossible écartée.

## Hypothèses vérifiées et écartées

- **`bundler ~> 4.0` serait une contrainte insatisfaisable** (`donico.gemspec:30`). Écarté : `gem list -re bundler` → 4.0.17 publié ; `Gemfile.lock` résout la contrainte sans conflit.
- **`Donico.root_dir` échouerait si `donico.gemspec` est absent de la gem installée** (`lib/donico.rb:69`, le gemspec n'est pas dans `s.files`). Écarté : `File.expand_path` n'exige pas l'existence du fichier, et `File.realpath` porte sur le **répertoire** parent, qui existe toujours.
- **`load_tasks` trierait les fichiers et chargerait `bake.rake` avant `common.rake`** (`lib/donico.rb:57`). Confirmé factuellement (`"bake.rake" < "common.rake"`) mais **sans conséquence** : les deux fichiers ne font que déclarer des tâches Rake, dont l'ordre de déclaration n'affecte ni la résolution ni les prérequis.
- **`Images::Docker#base_args` muterait un tableau partagé** via `super.prepend(...)` (`images/docker.rb:44`). Écarté : `Images::Base#base_args` construit un littéral de tableau neuf à chaque appel ; le `prepend` n'affecte que cette instance.
- **`platforms = <%= image.archs %>` produirait du HCL invalide** (`bakefile.erb:45`). Écarté : `Array#to_s` rend `["linux/amd64"]`, qui est une liste HCL valide — vérifié sur les 4 fixtures générées.
- **`[ -z "${VERSION+x}" ]` serait le même bug que `container_down`** (`.docker-in-docker.yml:36`). Écarté : ici la variable peut être réellement **non définie** (elle vient de la matrice GitLab), donc `${var+x}` distingue correctement les deux cas. Le bug n'existe que dans `donico.lib.sh:69`, où la variable est un paramètre local toujours défini.
- **`Tasks::Bake#clean` planterait comme `Tasks::Docker`** sur le chemin `rescue` de `run_cmd` (`tasks/bake.rb:34-48`). Écarté : il fait `logs.join("\n")` et non `logs.reject(&:empty?)` ; `[nil].join("\n")` retourne `""` sans lever. Seul le chemin Docker est atteint par `ERR-lib/donico.rb:137`.
- **La couverture SimpleCov à 83,5 % refléterait un risque réparti** — écarté : `lib/donico/images/*.rb` affiche ~100 % de lignes couvertes tout en contenant deux bugs prouvés. La couverture de lignes ne mesure ici que le passage, pas l'assertion (cf. `TEST-spec/donico/images:0`).

## Reste à traiter

1. **Comportement exact de `docker buildx bake` face à `${HOME}` dans un `src` de secret**

   Le fixture `spec/fixtures/bake/custom.yml` produit `src = "${HOME}/.aws/credentials"` dans le HCL généré. Que bake résolve `HOME` depuis l'environnement, exige une déclaration `variable "HOME" {}`, ou échoue, n'a pas pu être établi sans exécuter buildx contre un daemon Docker. Le finding `SEC-lib/donico/data/templates/bakefile.erb:24` a donc été formulé sur ce qui est certain (l'absence d'échappement des `"` casse le HCL de façon reproductible) et signale le `$` comme actif sans en trancher la résolution.

2. **Validation des templates GitLab CI contre un pipeline réel**

   Les quatre fichiers de `gitlab-templates/` ont été audités par lecture. Leur comportement effectif (résolution `extends`, disponibilité des variables de matrice, ordre `before_script`/`script`) n'a pas été exercé sur une instance GitLab ; les findings les concernant portent sur la logique shell et les commentaires, pas sur la sémantique du moteur de CI.

3. **Dépôts consommateurs**

   L'audit s'arrête aux frontières de ce dépôt. Les findings à impact aval — `API-lib/donico/rake/hooks.rb:22` (`after` inerte), `DOC-gitlab-templates/…:20` (détection `grep bake`) — supposent des usages dans les dépôts d'images (`donico`, `gitlab-runner`, …) qui n'ont pas été inventoriés. Savoir combien de `Rakefile` consommateurs utilisent réellement `after` conditionne la sévérité réelle du point 6 de l'ordre de remédiation.
